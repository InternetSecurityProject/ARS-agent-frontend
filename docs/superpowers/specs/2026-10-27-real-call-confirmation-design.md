# 서버 테스트 실통화 확인

사용자 승인: debug 서버 테스트에서 실통화를 허용하되, 번호와 실제 발신 경고를 확인한 뒤에만 시작한다. 기존 데모/미리보기는 유지하며 실제 발신 검증은 사용자가 직접 한다.

## 접근

서버 health가 sim이면 기존 테스트 시작, clawops이면 실통화 준비 → 확인창 → 실제 발신 순서다. 앱이 서버 모드를 바꾸지는 않는다. 알 수 없는 backend는 차단한다. 실통화 번호는 자동 입력하지 않고 사용자가 직접 입력한다.

확인창은 정규화/표시된 대상 번호, 목적, 실제 전화·이용 시간/요금 가능성, 서버 발신임을 알린다. API 키는 표시하지 않는다. 취소/닫기/복원은 발신하지 않고 확인은 매번 새로 요구한다. 확인한 번호·목적·모드를 Start 명령으로 묶고 입력을 바꾼 오래된 확인은 사용하지 않는다. 확인은 rememberSaveable에 넣지 않는다.

Start에는 ServerTestMode(Sim/RealCall)를 추가하며 기본값은 Sim이다. 컨트롤러는 발신 직전 health를 재조회하고 확인된 모드와 다르면 생성하지 않는다. 다른 활성 통화·중복 시작·생성 응답 유실 차단을 유지하고 mutation 자동 재시도는 추가하지 않는다. API 키/토큰은 기존처럼 비저장/로그 제외.

앱 음성 듣기·마이크 전달은 별도 미구현이라고 명시한다. 이 작업은 debug 테스트 경로만 바꾸며 본 앱과 갤러리, 앞서 준비한 B/C 렌더러, 백엔드 설정, 실제 발신, 푸시/병합은 변경하지 않는다. 검증은 FakeGateway·로컬 MockWebServer·합성 UI 데이터로만 한다.
