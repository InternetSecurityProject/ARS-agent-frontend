# API 연동 기반: 승인 범위

사용자가 선택한 1번: 기존 데모와 화면 미리보기를 유지하고, 통신 기반과 모의 서버 테스트만 준비한다.

- 근거: 백엔드 `docs/api-main-v0.3.yaml` 및 실제 `app.py`, `session.py`. 로컬 확인 commit `3887bc4`.
- 대안: 화면/ViewModel까지 서버 이벤트로 구동하는 방식은 이번에 제외한다.
- 세션 생성, 사용자 조작 6종, 진행 중/종료 결과, health, 이벤트 WebSocket을 독립 API 클라이언트로 만든다.
- Kotlin 직렬화 모델을 사용하고 snapshot, 상태, 자막, 경로, 요청, 요약, 종료를 해석한다. 알 수 없는 이벤트는 식별 가능하게 보존한다.
- 서버 주소·앱 키는 명시적인 런타임 설정으로 전달한다. 실제 주소/키의 기본값, 앱 실행 시 네트워크 요청, UI 연결은 추가하지 않는다.
- HTTPS/WSS 기본, 명시적으로 허용한 로컬 테스트 주소만 HTTP/WS. 외부 origin의 WebSocket에 세션 토큰을 전송하지 않는다.
- 세션 생성·조작 자동 재시도 없음. 토큰/민감정보 로깅·파일 저장 없음. 응답 본문을 예외 메시지에 넣지 않는다.
- 인증·오류·JSON·취소·WebSocket 재연결 후 snapshot을 로컬 MockWebServer로 검증한다. 실제 백엔드나 발신 서비스에 접속하지 않는다.
- 실제 STT/TTS, 전화 발신, 오디오 재생/마이크, 화면 데이터 매핑, 배포·원격 push는 제외한다.
- 민감정보의 입력 길이는 서버 계약 미확정이다. 통신 모델은 1~20자 규칙만 지원하며 6자리 자동 제출을 일반 계약으로 가정하지 않는다.

서버 주소 이후: 개발용 앱 키와 HTTPS/WSS 프록시 설정 확인 → health → 시뮬레이터 세션 검증 → 별도 작업에서 화면/오디오 연결.
