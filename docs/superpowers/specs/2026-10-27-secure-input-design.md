# C 개인정보 입력 — 명시적 완료

사용자는 서버 안내에 맞는 secure_input 화면과 전용 전송값 준비를 승인했고, 자리 수 계약 부재 설명 후 모든 개인정보 입력 화면에 ‘입력 완료’를 추가하도록 결정했다. 디자인/일반 전화/데모와 미리보기 진입은 유지하며 개인정보 자동 제출만 제거한다.

## 접근

기존 B 서버 렌더러에 선택적인 SecureInputInput(canSend, onSubmit, retryVersion)을 추가한다. 개인정보 키패드는 기존 원형 키패드를 카드 밖에 재사용하고 종료 위치를 유지한다. 서버 label/message(없으면 ars_prompt) 표시; 기대 길이를 문자열에서 추측하지 않는다. 1~20자의 API 제한만 적용하고 종료 기호는 서버가 붙인다. 지정된 단일 종료 키는 입력 키에서 비활성화해 중복 추가를 방지한다.

입력값은 화면 수명 내 CharArray 버퍼에만 보관하고 마스킹한다. 완료 버튼만 SessionAction.SecureInput(requestId, digits)을 생성하며 일반 Key/Answer를 사용하지 않는다. 요청 만료·교체·종료·백그라운드·화면 해제에 버퍼를 지우고 완료 시에도 콜백 전에 비운다. 입력값은 rememberSaveable/로그/파일에 저장하지 않는다. 전달용 immutable String 및 네트워크 내부 버퍼의 완전 삭제는 보장하지 않는다.

같은 요청은 한 번만 전달하고 화면 크기 변화나 요청 일시 제거로 중복 제출을 허용하지 않는다. 준비/연결 상태는 호스트가 전달하며 awaiting_user일 때만 입력한다. 불명확한 실패에 자동 재시도하지 않는다. 재입력은 새 요청 또는 명확히 미접수된 실패 후 호스트의 retryVersion 갱신으로만 가능하다.

데모의 6자리 예시는 유지하지만 여섯 자리 입력만으로 진행하지 않고 완료 버튼이 있어야 한다. 고정 미리보기는 버튼이 보이되 기존처럼 정지 상태다. debug 진단 화면도 완료 버튼 이름을 통일한다. 실제 서버 호출·새 아이콘·앱 서버 진입 연결·Figma 편집·푸시/병합은 제외한다.
