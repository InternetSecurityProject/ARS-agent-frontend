# 기본 앱 중심의 실제 ARS 통화 연결 설계

상태: 2026-10-27 사용자 승인. 기본 앱 버튼부터 B/C/D까지 설명한 흐름대로 실제 API 연결을 진행하며, 디자인·A 데모·미리보기를 유지하고 백엔드 수정과 구현자의 실제 발신은 하지 않는다. 이 세션에서 직접 구현·검증한다.

## 목적과 승인된 범위

사용자는 서버 테스트 화면이 아니라 기본 앱에서 실제 ARS 전화를 사용하는 것을 원한다. 기본 앱의 키패드·연락처 상세·통화 상세에 있는 기존 `ARS Agent 전화` 버튼에서 시작해 기존 B/C/D 디자인으로 서버 상태, 후보/개인정보 입력, Agent 음성 안내·답변, ARS 듣기를 연결한다.

- Kotlin/Compose, 기존 서버 API·이벤트·음성 모듈을 재사용한다. 백엔드와 Figma는 변경하지 않는다.
- A의 일반 전화, 예시 연락처/통화 목록, 화면 미리보기는 데모로 유지한다. Android 기본 전화앱 지정, SIM 발신, 실제 연락처/통화기록 접근은 추가하지 않는다.
- 서버의 070 회선이 대상 번호로 발신한다. 앱의 `일반 전화`는 여전히 실제 발신하지 않는다. 010 번호에는 Agent 버튼을 표시하지 않는 현재 규칙을 유지한다.
- 에이전트 실제 발신은 사용자가 확인창에서 직접 승인해야 한다. 구현자·테스트는 배포 서버의 세션 생성/액션 API를 호출하지 않는다.
- 새 런처 아이콘이나 서버 테스트 화면으로의 필수 우회는 만들지 않는다. 기존 서버 테스트 도구는 남긴다.

## 검토한 접근과 사용자의 선택

1. 서버 테스트에서 준비 후 B/C/D로 전환: 변경이 작지만 기본 앱에서 서비스를 이용하는 흐름은 완성되지 않는다.
2. **기본 앱의 Agent 버튼에서 실제 발신: 사용자가 선택.** 실제 이용 흐름이 한곳으로 이어지며, 기존 Agent 데모와 실제 통화를 명확히 구분해야 한다.

구현 제안: 기존 상단 `UI 데모` 메뉴 자리를 모드 선택에 재사용한다. 기본값은 `실제 ARS`로 하고 같은 메뉴 안에 `UI 데모`와 기존 예시 시나리오를 남긴다. 통화/발신 준비 중에는 모드를 바꿀 수 없다. 갤러리는 항상 고정 데모이며 실통화 호스트를 생성하지 않는다.

## 화면과 사용자 흐름

### 발신 전: 기존 B01 형태

번호 입력 또는 예시 상세 → `ARS Agent 전화` → 기존 B01 목적 입력 화면. 번호와 취소(X) 버튼, 밝은 배경, 카드와 하단 위치를 유지한다. 이 시점에는 세션 생성과 실제 발신을 하지 않는다.

- 목적은 직접 입력하거나 기존 마이크 버튼으로 말한다. 첫 음성 사용에는 음성 인식 서비스의 외부 전송 가능성 안내와 마이크 권한을 요청한다. 허용하면 목적 듣기를 시작한다. 거절하면 글자 입력으로 계속할 수 있다.
- 목적이 명확해지면 기존 자동 진행 타이밍에 맞춰 **발신 확인창까지만** 연다. 목적 입력/수정 자체로는 발신하지 않는다.
- 기존 실통화 확인창을 재사용하여 대상 번호·목적·실제 발신/요금 안내와 비밀번호 형태의 API 키 입력칸을 보여준다. 키를 별도 설정 페이지에서 저장하지 않는다.
- 확인창의 `실제 발신`을 누른 경우에만 현재 번호·목적·키를 소비하여 요청을 한 번 보낸다. 키는 요청으로 넘긴 직후 입력칸에서 지운다. 자동 재발신은 없다. 취소하면 B01로 돌아간다.
- 번호/목적이 바뀌거나 화면을 나가면 기존 확인은 폐기한다. B01 취소는 진입했던 A 화면으로 돌아간다.

### B: 서버 진행 화면

기존 번호/기관/시간 헤더, 진행 카드, 60dp 원형 보조 버튼 세 개, 72dp 종료 버튼의 위치·색·크기를 유지한다. 예시 날씨나 데모 타이머가 서버 상태를 덮어쓰지 않는다.

- 세션 생성 후 같은 호스트가 이벤트를 구독하며 기존 `BCallData`와 `BServerCallScreen`에 최신 상태·경로·ARS 자막·요약을 전달한다.
- 진행 카드에는 현재 필요한 상태와 안내를 보여준다. 오류·전송 중·재연결·최종 결과 조회는 카드 안에 간결하게 제공하고 별도 테스트 화면으로 보내지 않는다.
- 서버가 시작 시각을 주지 않으므로 통화 중 시간은 첫 연결 상태를 수신한 시점부터 앱이 측정한 경과 시간이다. 발신 중에는 시간을 시작하지 않는다. 종료 결과의 소요 시간이 도착하면 서버 값을 우선한다. 화면 크기 변경으로 시간이 초기화되지 않는다.
- 서버의 통화 모드가 예상과 다르거나 다른 세션이 활성 상태이면 발신하지 않고 설명한다. 키 인증 실패, 네트워크/이벤트/오디오 실패를 구분한다.
- 세션 생성 결과가 불확실하면 다시 발신하지 못하도록 유지한다. 액션 처리 불확실성도 자동 재전송하지 않는다. 상태 재연결은 기존 세션의 이벤트만 다시 구독한다.

### C: 후보 선택·답변·개인정보·수동 키패드

- 서버의 `request`에 따라 기존 C 디자인을 선택한다. 후보 번호·이름·질문·입력 안내는 서버 값이며 임의 예시로 대체하지 않는다.
- 후보 버튼은 `select`, 일반 답변은 `answer`, 개인정보는 `secure_input`, 요청 없는 수동 키패드는 `key`로 전송한다. `request_id`·기한·세션·현재 전송 가능 여부를 화면과 소유자 양쪽에서 확인한다.
- 일반 질문은 기존 입력 디자인의 실제 마이크와 글자 입력을 연결한다. Agent가 질문을 읽은 뒤 자동으로 답변을 듣고 최종 인식 결과를 한 번 전송한다. 말하기 재시도·중지는 카드 안에서 제공한다. 글자 답변에는 명시적인 전송 동작을 제공한다.
- `critical_action`은 서버 후보 버튼만 허용하고 음성·자유 입력은 제공하지 않는다. 개인정보는 기존 카드 밖 키패드와 `입력 완료`를 유지하며 음성 입력/읽어주기를 하지 않는다. 종료 기호는 서버가 붙인다.
- 민감 입력은 저장 상태·로그·분석·화면 캡처에 남기지 않는다. 전송·요청 변경·기한 만료·연결 상실·백그라운드·종료 시 폐기한다.
- 빠른 중복 탭, 음성/버튼 동시 응답, 화면 재구성으로 같은 요청이 중복 전송되지 않는다. HTTP 409/전송 결과 불확실 후에는 재연결 전까지 다시 보내지 않는다. 재연결만으로 이미 보낸 화면 입력을 자동 재전송하지 않는다.
- 수동 키패드는 전송 가능한 상황에서만 각 키를 즉시 보낸다. 개인정보/후보 요청 중에는 수동 `key`로 우회하지 못하게 한다. 새 요청이 오면 그 입력 화면을 우선한다.

### 하단 버튼·음성·오디오

- `ARS 소리 켜기/끄기`는 기존 수신 전용 오디오 경로에 연결한다. Agent TTS/STT 중에는 잠시 억제하고 지난 오디오는 쌓아두지 않는다.
- `키패드`는 위의 실제 키 전송 기능을 열고 닫는다. `오디오`는 기존 팝업 디자인을 유지하고 기기가 제공하는 휴대전화/스피커 출력에 연결한다. 지원하지 않는 출력은 성공한 것처럼 표시하지 않는다. 시스템 오디오 설정은 통화 화면을 벗어나면 복원한다.
- Agent 음성 사용 여부·듣는 중/안내 중·권한/엔진 오류는 진행 카드 내부의 최소 요소로 제공한다. 기존 큰 서버 테스트용 음성 패널을 통화 화면 위에 얹지 않는다.
- `종료`는 실제 서버 취소 액션을 전송하고 종료 확인을 기다린다. 누르는 즉시 로컬 데모 종료 화면으로 바꾸지 않는다. 취소 실패 시 재연결/결과 확인을 제공한다.
- 뒤로가기는 키패드/팝업을 먼저 닫고, 활성 세션을 방치한 채 A로 돌아가지 않는다. 확인 없이 세션 생성/취소를 추가하지 않는다. 서버 종료를 확인한 다음 A로 돌아갈 수 있다.

### D와 종료

`waiting_agent`와 `connected_to_agent`를 기존 D 통화 틀에 표시한다. 실제 상담원 연결 상태에서는 Agent의 답변 듣기와 ARS 재생을 중단한다. 상담원과의 사용자 음성 통화는 지원하지 않는다고 알리고, 서버 세션이 종료됐다고 거짓 표시하거나 임의로 취소하지 않는다.

`agent_done`/요약 도착/상담원 연결만으로 종료로 간주하지 않는다. `ended`, 최종 REST 결과 또는 서버가 완료한 취소 응답으로 종료를 판단한다. 최종 결과와 서버 통화 시간을 표시하고 A로 돌아간다.

## 코드 경계와 개인정보

- 기본 앱에 실통화 호스트를 연결하되 기존 `AppViewModel`/리듀서는 일반 전화·Agent 데모용으로만 유지한다. 실통화 중에는 데모의 자동 진행을 사용하지 않는다.
- 현재 debug에 있는 controller/gateway/음성 공통 코드를 재사용 가능한 main 계층으로 옮겨 기본 앱과 기존 서버 테스트가 함께 사용하도록 한다. 클래스 이름 정리만을 위한 큰 리팩터링은 하지 않는다.
- 실제 음성 기능에 필요한 마이크 권한·STT/TTS 서비스 검색을 공통 manifest에 선언한다. 일반 A 데모·갤러리를 여는 것만으로 마이크를 요청하거나 음성을 초기화하지 않는다. SIM/전화·연락처 권한은 추가하지 않는다.
- 키·세션 토큰·민감 입력·음성 원문은 영구 저장하지 않는다. 실통화 준비/세션 화면에 보안 캡처 방지를 적용한다. 액션/키를 디버그 출력에 넣지 않는다.
- 세션은 화면 재구성에서 중복 생성하지 않으며, 앱 프로세스 재시작에서 자동 복원/재발신하지 않는다. 백그라운드에서는 STT/TTS와 ARS 재생을 멈추지만 이것을 서버 통화 종료로 표시하지 않는다. 다시 음성을 켜는 동작은 명시적으로 받는다.

## 구현자가 결정할 세부사항

기존 디자인의 여백·색·컴포넌트를 그대로 재사용하는 범위 안에서 파일 분리, 콜백 타입, 테스트 유틸리티를 결정한다. 일반 답변/오류/음성 상태의 간결한 문구는 새 페이지나 새로운 주 작업 버튼을 추가하지 않는 방향으로 정한다.

## 검증과 비목표

MockWebServer·가짜 음성 장치·합성 서버 이벤트로 기본 앱 진입부터 단일 발신 요청, 상태 전환, 후보/답변/개인정보/키 전송, 음성 충돌, 상담원 연결, 종료, 복원/중복 방지를 검증한다. 전체 JVM/UI 테스트와 lint/debug/release APK를 실행한다. A/갤러리는 기존 회귀 테스트와 대표 화면으로 비교한다.

에뮬레이터에 최신 APK를 설치하고 실제 발신 직전까지만 확인한다. 실제 전화, 실기기 음질/인식 정확도, 배포 서버 오디오의 종단간 성공은 사용자가 직접 확인할 항목이며 구현자가 검증 완료로 주장하지 않는다. 백엔드 수정, 자동 실제 발신, 상담원 음성 송신, SIM 전화앱 대체, 추가 런처, 푸시/병합은 범위 밖이다.
